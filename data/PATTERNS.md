# データ入力 早見表（2026.08.03時点）

`data/kinggnu-discography.json` / `data/srvvinci-discography.json` に新しい曲・情報を追加するときの「型」の一覧です。
迷ったら、まず**一番近いパターンを探して、既存のエントリをコピーして書き換える**のが基本です。

JSONを保存する前に、VS Codeで赤い波線（構文エラー）が出ていないか必ず確認してください。

---

## 1. King Gnu：普通の1曲（`items[]`）

一番よく使う基本形。単独でリリースされた曲はこれ。

```json
{ "type": "配信SG", "year": "2024.10.21", "title": "ねっこ", "slug": "nekko",
  "note": "TBS系日曜劇場『海に眠るダイヤモンド』主題歌",
  "extra": "【概要】\n・◯◯\n\n【豆知識】\n・◯◯",
  "yt": "動画ID（YouTubeのURLの v= の後ろの部分）",
  "spotify": "SpotifyのURL", "lyrics": "歌詞サイトのURL" }
```

- `type` は `CDSG`（CDシングル） / `配信SG`（配信シングル） / `COVER`（カバー曲） / `UNRELEASED`（未音源化）のどれか
- `slug` は他のどのエントリとも被らないこと（迷ったら英語タイトルを小文字ハイフン区切りにする）
- `extra` は `【概要】`と`【豆知識】`の2段構成が今の標準。両方書かなくてもよい
- `note`・`spotify`・`lyrics`は情報がなければ `""`（空文字）でOK

---

## 2. King Gnu：カップリング（両A面/2曲入りシングル）

1枚のCDシングルに2曲入っていて、それぞれ別の曲詳細ページを持たせたい場合。
（例：BOY／F.O.O.L、一途／逆夢、三文小説／千両役者）

```json
{ "type": "CDSG", "year": "2021.12.01", "title": "BOY", "slug": "boy",
  "displayTitle": "BOY/F.O.O.L", "note": "...", "extra": "...",
  "yt": "...", "spotify": "...", "lyrics": "...",
  "coupling": {
    "title": "F.O.O.L", "slug": "fool", "note": "...", "extra": "...",
    "yt": "...", "spotify": "...", "lyrics": "..."
  }
}
```

- 親（表側の曲）は普通の1曲と同じ書き方に `"coupling": {...}` を追加するだけ
- `coupling`の中身も、普通の1曲とほぼ同じ形（`slug`は親と別のものを付ける）
- `displayTitle`は一覧表示用の見出し（省略可、なくても動く）

---

## 3. King Gnu：アルバム収録曲（`albums[].tracks[]`）

既存アルバム（THE GREATEST UNKNOWNなど）に曲を追加する場合は、そのアルバムの`tracks`配列に追記する。

```json
{ "num": 4, "title": "Specialz", "slug": "specialz-album",
  "yt": "動画ID", "note": "...", "spotify": "...", "lyrics": "..." }
```

- `num` はアルバム内のトラック番号
- `slug`は、同じ曲が単独シングルにもある場合（再録・ALBUM ver.など）、単独版と被らないよう接尾辞を付ける（下記4章参照）
- **新しいアルバムを丸ごと追加する**場合は、`albums[]`に新しいオブジェクトを1つ追加する必要があり、これは既存のアルバム（例：`"title": "THE GREATEST UNKNOWN"`のブロック）を丸ごとコピーして、`title`・`year`・`note`・`extra`・`tracks`を書き換えるのが安全

---

## 4. slugの命名ルール（重複を避ける接尾辞）

同じ曲が複数バージョンで存在する場合、素のスラッグ（例：`specialz`）は**最初に出てくるバージョン**（だいたい単独シングル）に使い、他のバージョンには文脈を表す接尾辞を付ける：

| 状況 | 接尾辞の例 |
|---|---|
| アルバム収録版（再録） | `-album` / `-album-ver` |
| ライブアルバム収録版 | `-dome-tour-live` |
| 配信シングル版とミニアルバム版で曲名が同じ | `-single` / `-tokyo-chaotic` など収録作品名 |
| King Gnu版とSrv.Vinci版で読みが同じ（例：泡／ABUKU） | 片方は素のまま、もう片方に `-single` 等 |

**一番大事なルール：同じslugを2箇所に使わない。** 迷ったら似た曲の接尾辞パターンを真似する。

---

## 5. Srv.Vinci系（`groups[].demos/singles/albums`）

- 単独の曲（コレクションに属さない） → `demos`か`singles`に直接オブジェクトを追加（`tracks`キーを持たない）
- デモ集・ミニアルバムなど複数曲入り → `demos`/`singles`/`albums`のオブジェクトに`"tracks": [...]`を持たせ、中の各曲は King Gnu のアルバム収録曲と同じ形（`num`, `title`, `slug`, `yt`, `note`, `extra`, `spotify`, `lyrics`）
- `appleMusic`：Apple MusicのURL（Srv.Vinci系のみ使うことがあるフィールド、なければ省略可）

---

## 6. 特殊フィールド一覧（使うのは一部の曲だけ）

| フィールド | 意味 | 例 |
|---|---|---|
| `yt2` | 2本目の動画（MV欄に2つ並べて表示） | SO BADの2本目の動画ID |
| `tweets` + 本文中の`{{TWEETS}}` | 豆知識の途中にX(旧Twitter)投稿を埋め込みカルーセル表示 | `"tweets": ["https://x.com/.../status/..."]` を配列で並べ、`extra`本文の埋め込みたい位置に`{{TWEETS}}`という文字列を書く |
| `hideVideo: true` + `externalVideo` | 公式じゃない動画（ファン転載など）へのリンクは非表示にしつつ、そのURL自体はページの裏で保持しておく | Catch!!!など |
| `shorts` | YouTube Shorts動画IDの配列（あれば下部に表示） | `"shorts": ["動画ID", ...]` |
| `displayTitle` | 曲一覧などでの表示名を`title`と別にしたいとき | `"一途/逆夢"`など |
| `albumText` | 「V.A.（オムニバス）収録」など、通常のアルバムリンクと違う出典表記をしたいとき | `"V.A. 井上陽水トリビュート"` |

**基本方針：** 上の特殊フィールドは全部「なくても動く」オプション項目です。分からなければ最初から書かなくてOK。普通の1曲として登録されるだけで、サイトが壊れることはありません。

---

## 7. Blu-ray/DVD（`discs`を持つitems）について

`items[]`の中には稀に`"discs": [...]`を持つエントリ（例：Dome Tour Blu-ray）がありますが、これは曲データではなく映像作品の収録内容リストで、`video/`ページ専用の別の仕組みです。曲の追加とは無関係なので、真似しなくてOKです。

---

## 困ったときの原則

1. 一番似ている既存の曲をコピペして書き換える
2. `slug`は他と絶対に被らせない（不安なら「タイトル-年」など長めにしても動く）
3. 特殊フィールドは分からなければ書かなくていい（普通の曲として登録されるだけ）
4. 保存前にVS Codeの赤い波線（構文エラー）がないか確認する
5. それでも不安なときは、そのまま保存せず一旦置いておいて、次にAIに聞けるタイミングで確認する
